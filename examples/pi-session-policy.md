# Pi use in Codex sessions

Ask once at each new session for AUTO, ON, or OFF. Apply a clear initial selection without repeating the question. Before an answer, do not automatically launch Pi.

AUTO: Delegate bounded work when the expected benefit justifies prompting, cost, coordination, review, and rework. Otherwise work directly.

ON: Actively look for useful bounded Pi work and prefer it when net benefit is positive. This is a preference, not mandatory delegation. File count and task type alone do not require a launch.

OFF: Do not automatically launch Pi. Explicit later Pi requests may authorize bounded work under project rules.

MCP orchestration defaults OFF and is independent of this choice. OFF/UNKNOWN orchestration permits Pi when the separate preference allows it. Codex native subagents remain governed by Codex and project rules. A denied mode-setting call does not imply that all MCP tools are unavailable. Follow a user answer in the current conversation; an optional tool write can persist it to hooks, but do not repeat the preference question or silently overwrite the answer if the tool is denied.

MCP worker routing uses pi/pi-balanced/max. Respect each project's Pi prohibitions and set blocked roots for private directories.
